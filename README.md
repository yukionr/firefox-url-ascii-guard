# Firefox URL ASCII Guard

明示的なプロトコル付き URL のドメイン部分に英数字・URL 用記号以外の文字が含まれると、Firefox Nightly の URL バーだけを赤くする拡張です。入力中の検索キーワードは無視します。ツールバーボタンの `!` とツールチップでも検出状態を確認できます。

## 判定

対象は `http:`、`https:`、`ftp:`、`ftps:`、`sftp:`、`file:`、`ws:`、`wss:` で始まる文字列です。大文字・小文字は区別しません。プロトコルのない入力、`about:`・`data:`・`javascript:` などの内部・特殊 URL、未知のプロトコルは対象外です。

対象 URL のドメイン部分（ホスト名）だけを検査し、次のいずれかで警告します。ユーザー名・パスワード、ポート、パス、クエリ、フラグメントは検査しません。ホスト名のないローカルの `file:` URL も警告しません。

- `A–Z`、`a–z`、`0–9` と `-._~:/?#[]@!$&'()*+,;=%` 以外の文字。
- ホスト名のラベルが `xn--` で始まる国際化ドメイン。ブラウザーが Punycode に変換した後でも検出します。
- `%E6%97%A5` などの非 ASCII バイト。不正な UTF-8 の高位バイトも検出し、二重符号化の再帰的な復号はしません。

| 表示・入力の例 | 動作 |
| --- | --- |
| `日本語の検索` を入力中 | 無視・通常色 |
| `site:example.test 日本語` を入力中 | 無視・通常色 |
| `example.test/記事` を入力中 | 明示的なプロトコルがないため無視 |
| `https://example.test/path?q=123` | 通常色 |
| `https://еxample.test/` | 赤・`!` |
| `https://xn--e1afmkfd.test/` | 赤・`!` |
| `ftp://例え.test/` | 赤・`!` |
| `https://example.test/記事?q=日本語#見出し` | 通常色 |
| `https://example.test/%E6%97%A5` | 通常色 |

入力中は URL バーの文字列からホスト名を検査します。編集中でなければ選択中タブの実際の URL を使うため、Firefox がプロトコルを省略表示していても判定できます。検索実行後の結果ページもホスト名だけを判定するため、パスやクエリに含まれる日本語の検索キーワードでは警告しません。

赤はドメイン部分の対象文字の存在を示し、詐欺の断定ではありません。日本語の正規ドメインも対象です。通常色もサイトの安全性を保証しません。ASCII だけの偽ドメインは検出しません。

## Nightly 専用の実装と権限

0.2.0 は WebExtension Experiment を使います。通常の WebExtension API では、入力途中の文字列の取得や、テーマ全体に影響しない URL バーだけの装飾ができないためです。

**実験 API の実装はブラウザー内部を操作できる強い権限で動作します。** 通常の拡張の権限分離より広いアクセスが可能です。この実装が行うのは、URL バー・選択中タブの参照、入力・移動の監視、URL バーに限定した CSS の追加・解除、状態通知です。外部からスクリプトや CSS を取得する仕組みはありません。

- テーマ API は使いません。選択中のテーマや他の入力欄の配色を変更しません。
- CSS は専用属性を付けた `#urlbar` の背景・入力領域だけを対象にします。
- 拡張の無効化・削除時は CSS、属性、イベント監視を解除します。
- ページ本文の参照、履歴や入力の保存、URL・検索語の外部送信は行いません。
- `tabs` 権限は状態ボタンの更新に使います。実験 API 自体はこの権限に制限されません。

Nightly / Developer Edition 向けで、`extensions.experiments.enabled=true` が必要です。未署名 XPI の恒久利用には `xpinstall.signatures.required=false` も必要です。通常版 Firefox 向けの拡張として配布するものではありません。設定変更はビルドや検証スクリプトでは利用中のプロファイルに対して行いません。

## ビルドと読み込み

Node.js と Python 3 を使い、追加パッケージは不要です。プロジェクトのルートディレクトリで実行してください。

```sh
npm test
npm run build
```

ビルドは共通ロジックと実験 API を `experiments/urlbar/bundle.js` にまとめ、必要なファイルだけを `dist/firefox-url-ascii-guard-0.2.0.xpi` に格納します。生成された bundle を直接編集しないでください。

一時的に試すには、実験 API を許可した Nightly の `about:debugging#/runtime/this-firefox` から「一時的なアドオンを読み込む」を選び、XPI を指定します。ビルド後ならこのフォルダーの `manifest.json` も使えます。一時読み込みは Firefox 終了時に解除されます。

恒久的にインストールするには、必要な設定を有効にした Nightly の `about:addons` を開き、歯車メニューの「ファイルからアドオンをインストール」から、ビルドした XPI を選択してください。

プロファイルへ配置した場合は Nightly の完全終了と再起動が必要です。0.1.0 からの更新でも拡張 ID は `url-ascii-guard@local.invalid` のままです。

配置した XPI の一致だけでは、実行中の拡張が更新された証明にはなりません。`about:addons` の登録バージョンも確認してください。0.1.0 → 0.2.0 の更新では、ファイルは 0.2.0 でも拡張登録と起動キャッシュに 0.1.0 が残るケースを確認しました。この場合は終了中にキャッシュをバックアップして再生成する必要があります。実行中の登録ファイルを直接編集しないでください。

## 検証

```sh
python3 tools/smoke-firefox.py
```

既定では PATH 上の `firefox-nightly` を使います。別の名前や場所にある場合は、`--firefox` で実行ファイル名またはパスを指定してください。ディスプレイ関連の環境変数は実行元から継承します。

このスクリプトは一時プロファイルを作り、そこだけで実験 API を有効化します。ローカルの HTML ファイルと WebDriver のキーボード操作を使い、`https://日本語.test/` の入力時の警告・検索キーワードの除外・ライト／ダーク設定・テーマ配色の維持・削除時の解除を検証します。入力したドメインへの移動は行いません。普段のプロファイルは使いません。

ただし、現在のスクリプトには、日本語のファイル名を含むローカルの `file:` URL で警告するという旧仕様の期待が残っています。ホスト名だけを判定する現仕様ではこの期待を満たさないため、現仕様の GUI 検証に使う前にスクリプトの更新が必要です。

2026-10-17、ホスト名だけを判定する現在の実装で次を確認しました。

- `npm test` の Node.js テスト 10 件が成功。対象プロトコル、キーワードの除外、国際化ドメイン・ホスト名内の符号化文字、ホスト名以外の除外、移動・タブ変更・入力取り消し相当の状態更新、監視解除を確認。
- `npm run build` が成功。XPI の ZIP 整合性と格納された manifest の一致をビルド処理内で確認。

同日の 0.2.0 の以下の確認記録は、ホスト名だけに判定を限定する前の実装に対するものです。現在の実装でのブラウザー検証は未実施です。

- Firefox Nightly 160.0a1 の隔離した headless プロファイルで XPI の読み込みに成功。
- ライト・ダーク設定で、非 ASCII URL は赤い背景と白い文字になり、キーワードを入力すると通常色へ戻ることを確認。
- 警告前後で、ナビゲーションバー・タブバーの算出済み背景色とテーマ属性が変わらないことを確認。
- 拡張の削除で URL バーの色が元に戻ることを確認。

headless での DOM・算出済みスタイルと入力イベントによる確認です。スクリーンショットの目視確認、Wayland 仮想画面・実ディスプレイの描画、HiDPI、プライベートウィンドウ、他の拡張との併用は未検証です。Firefox の内部 UI に依存するため、Nightly の更新で追従が必要になる場合があります。
